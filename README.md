# QUEST ARCADE — 无限树形清单（原生版 v2）

一个无需构建、无需 npm 的移动端优先网页原型，技术栈仅 **HTML + CSS + JavaScript**，深色科幻手游风格。

## 这版最重要的规则

**只有「清单」一种数据类型，没有独立的任务。** 每个清单都可以拥有任意多个子清单，子清单也能继续拥有子清单，理论上不限制嵌套深度。

- **叶子清单（无子清单）**：用户可以手动完成 / 取消完成。
- **父清单（有子清单）**：不可手动完成，**所有直属子清单完成后自动完成**。
- **逐级通关**：最后一个子清单完成时，沿着父级自动判定，可以连续解锁多层祖先清单。
- **重新打开**：任意子清单恢复待办，会自动取消未满足条件的所有上级清单的完成状态。
- **继续拆解**：已完成叶子清单一旦新增未完成子清单，就升级为父清单并重新进入待办；不会把新加内容当作已完成。
- **经验和升级**：包括自动通关的父级清单在内，每个完成的节点都按自身难度贡献 XP；取消完成会同步重新计算 XP。不会为每次页面刷新重复发放奖励。
- **完成进度**：父清单以其所有叶子后代为统计单位，例如 3/5；没有存储冗余的父完成标志。

### 例子

```
开发 APP  ◯
├── 界面设计  ◯
│   ├── 登录页面  ◯
│   │   ├── 绘制页面原型  ✓
│   │   └── 设计交互动效  ◯
│   └── 整理图标资源  ◯
└── 后端接口  ◯
    └── 设计数据结构  ◯
```

当「设计交互动效」完成时，「登录页面」自动通关，但「界面设计」暂不通关，因为「整理图标资源」尚未完成。

## 页面和功能

- **进行中**：树形清单目录、展开折叠、导航、重命名、移动层级、删除时提升子节点；当前层级清单卡片与叶子完成操作。
- **已完成**：所选清单子树下的全部已完成清单历史，允许取消叶子完成状态。
- **游戏化**：彩色粒子、自动连锁通关弹窗、XP、等级、连续挑战、徽章。
- **日历**：清单可设置计划时间及提醒、导出 `.ics`；网页打开且满足权限时轮询通知（不是可靠的后台闹钟）。
- **AI 参谋演示**：本地规则解析自然语言和 `项目 > 阶段 > 事项` 结构化路径，提供确认预览，**不是真实大模型**。正式调用大模型需要后续开发后端代理，不能把 API Key 写在浏览器代码里。
- **离线保存**：使用 `localStorage`。刷新保持数据。

## 运行方式

双击 `index.html` 即可打开（部分浏览器在 `file://` 环境限制通知）。也可使用 VS Code Live Server，或终端运行：

```sh
cd quest-arcade
python -m http.server 8000
```

然后打开 `http://localhost:8000`。

## 从旧版迁移

会识别旧版 `quest-arcade-save-v1` 存档（v1 / v2），把旧「清单」转换为父节点、旧「任务」转换为叶子清单，并保留任务完成状态、截止日期、提醒、备注等信息。

首次迁移时自动把原始存档备份到 `localStorage` 的 `quest-arcade-v2-backup`；新版用统一节点格式 `version: 3` 保存。

## 数据模型

所有清单都属于同一个 `nodes` 数组，每个节点有 `id`、`parentId`、`name`、`manualDone`、`completedAt`、`xp`、`due` 等属性。父级完成状态与进度通过非递归后序遍历计算，不需要存储父完成标志，也没有固定层数。

## 注意

这是一份 **APP UI/交互原型**，不是后台系统。提醒需要页面运行，原生闹钟和系统日历写入要在后续 App 中接入平台权限/服务。无限深度是数据模型层面成立；非常庞大的树可能需要虚拟列表或性能优化。
